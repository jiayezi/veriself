# 代码阅读顺序（给熟悉 `python-data-service` 的你）

## TL;DR —— 如果只记一行

> **`veriself/metrics/*.yml`（契约）→ `config.py`（常量）→ `warehouse/schema.sql`（数据模型）
> → `materializer/`（指标怎么算）→ `semantic/{contract,query,enforcement,compiler}.py`（最重要的部分）
> → 最后才看 `interfaces/`**

**先读约 4000 行的"契约 + 数据 + 语义"，再读 1800 行的接口层。** 顺序反了会看不出主线。

## 为什么不能从 `main` 开始读

`python-data-service` 的控制流是"请求进来 → 逐层往下找"，从 `main.py` 顺着走就能看懂。
`veriself` 的控制流是"**契约决定一切**"：指标口径、可用维度、权限策略、血缘、上卷方式
全写在 `veriself/metrics/*.yml` 里，Python 代码只是执行者。

所以正确的起点是**契约和数据模型**，不是入口函数。如果你从 `cli.py` 开始读，会看到大量
`gateway.py` 的适配代码，反而抓不到主线。

**另一条心理准备**：这个项目的代码量分布是反直觉的——`interfaces` 最厚（2347 行），
但它**几乎没有业务逻辑**；真正有含金量的是 `semantic`（2149 行）和 `materializer`（6 个文件，约 940 行）。

#### `sqlbuild.py` 内部怎么跳

这个文件仍是「先模板、后组装」。模板左对齐书写，缩进由 `_indent_block()` 统一施加。

| 顺序 | 看什么 | 为什么 |
| --- | --- | --- |
| 1 | 模块顶部 `_SPINE_*` / `_SOURCE_CTES` / `_DAILY_SRC` / 三个 `_ROLLUP_*` | 先看模板，就知道求值 SQL 长什么样。`_ROLLUP_DAILY` 原样落库；`_ROLLUP_BUCKETED` 每桶 `arg_max` 取代表行；`_ROLLUP_BUCKET_DECLARATIVE` 按契约的 `bucket.agg` 做桶内聚合 |
| 2 | `_row_expression` | 契约公式 → 可执行裸列表达式。**三步**：物理表名→别名、`metric('X')`→`up_X`、再去掉别名前缀。解析交给 `veriself/sqlrefs.py`（sqlglot AST），注释和字符串字面量不会被当成引用 |
| 3 | `_touches` + `_lateral_joins` | 公式引用了哪些来源 → 决定日期骨架；上游指标用显式 `LATERAL` 注入，关联条件写在 `ON` 里 |
| 4 | `_compute_ctes` | 选骨架 → 选上卷方式 → 填模板。返回值以具名 CTE `rolled` 结尾，`merge` 自己接 `SELECT ... FROM rolled` |

#### 两个必须看懂的点（否则会误读整个包）

**① 为什么是「三步合并」**

`merge.py` 里 `build_merge_sql` 的 docstring 记录了两次实测失败，值得逐字读：

```
① 关闭「值或口径变化」的有效行   → valid_to = batch_ts
② 插入临时表里「当前无有效行」的键（含刚被①关掉的）→ 新值进来
③ 关闭「本批次未产出」的键       → 不再有僵尸有效行
```

- 单条 `MERGE ... USING (WITH ...)` → DuckDB **Parser Error**（`USING` 子查询里不允许 `WITH`），所以先把本批次结果落到临时表；
- 单条 `MERGE` 加 `WHEN MATCHED AND <值不同>` → DuckDB 在条件不成立时**不再尝试后续分支**，
  于是「值变化」的键只被关闭、新值永远插不进去（实测有效行数反而少 1）。

三个步骤合起来覆盖三种情形，且**无变化时零写入**——这就是「重算幂等」的实现。
值比较还带浮点容差（`_values_equal` / `VALUE_REL_TOL`），因为 DOUBLE 求和顺序不稳定，
末位会在 `3599.53` 与 `3599.5300000000007` 之间摆动；不忽略它，每次重算都会留下假历史。

**② 上卷有三条路，窗口公式不能再套聚合**

`_compute_ctes` 按这个优先级选模板：

1. 契约写了 `bucket.agg` → `_ROLLUP_BUCKET_DECLARATIVE`。`formula_sql` 是日粒度标量，桶内聚合由物化器完成，`date_key` 取桶内最后一个有数据的真实日期。
2. 公式含 `OVER()` → `_ROLLUP_DAILY`，**原样落库**。7 日滚动和已经是跨时间逻辑，再套一层 `mean` 会把它二次平均。
3. 其余非日粒度（旧形态：公式里用 `CASE` 标记代表行）→ `_ROLLUP_BUCKETED`，每桶 `arg_max(daily_value, date_key)`。

`bucket.agg` 与手写 `OVER()` 在契约加载期就互斥（`test_load_contracts_rejects_bucket_with_window_formula`），物化时不会两条路同时成立。
跨粒度上卷（日 → 周/月的查询期聚合）仍由 semantic 编译器按契约的 `agg` 负责，物化阶段不做这件事。

#### 读完后你应该能回答

- 为什么 `_channel_agg_sql` 里的每个通道都必须带 `FILTER (WHERE channel = ...)`？
  （`fact_observation` 是窄表，漏掉过滤会让每个通道列变成「当天全部通道的聚合」）
- 为什么含 `OVER()` 的公式在物化时不能再套一层聚合？（否则 7 日滚动和会被二次平均）
- `bucket.agg: sum` 和旧的「窗口 + `CASE` 代表行」各走哪个模板？
  （前者 `_ROLLUP_BUCKET_DECLARATIVE`，后者 `_ROLLUP_BUCKETED`）
- 为什么物化**不做物理 `DELETE`**？（删了就永久失去 as-of 复现能力；关闭只是写 `valid_to`）
- 为什么「关闭旧行」必须限定 `metric_version`？（否则物化 v2 会关掉 v1 的有效行，
  按旧口径回溯直接失效。范围条件在 `build_merge_sql` 的 `scope` 里）

### ⚠️ 示例 3 的 filters 参数写法（我踩过的坑）

`--filters` 是 JSON 字符串，**在 PowerShell 里用单引号包裹、内部双引号不要转义**：

```powershell
--filters '{"date.last_n_days":30}'          # ✅ 正确
--filters '{\"date.last_n_days\":30}'        # ❌ 反斜杠会被原样传入，报查询对象非法（退出码 4）
```

| `partner` | **0 行** | 隐私闸门：`HAVING COUNT(DISTINCT subject_id) >= 5` 不满足 |
| `researcher` | **0 行** | 同上 |

**这不是 bug，是刻意的**：`subject.daily_steps` 的 `rls_policy` 是 `aggregate_min5`，
而合成数据只有 1 个主体。把两个角色的 `audit.compiled_sql` 对比一下，你能清楚看到
`partner` 的 SQL 多了 `HAVING COUNT(DISTINCT "f"."subject_id") >= 5 AND COUNT(*) >= 5`——

```sql
-- partner 的编译结果（节选）
... GROUP BY 1 HAVING COUNT(DISTINCT "f"."subject_id") >= 5 AND COUNT(*) >= 5 ORDER BY "date.month" ASC LIMIT ?
```

这正是 `enforcement.py::check_rls` 的产出。**想让它返回数据，需要 v0.2 的"多主体"工作**
（见 `veriself/docs/03-路线图.md` 第 1 项）——我拒绝为了让 demo 好看而放宽这道闸门。

### 🔬 最值得做的实验二：改一行 YAML，看系统行为立刻变化

```powershell
# 打开 veriself/metrics/subject.sleep_debt_7d.yml：
#   把 allowed_dimensions 里的 date.weekday 删掉，或把 agg 从 mean 改成 sum，然后：
veriself metrics show subject.sleep_debt_7d                                       # contract_hash 变了
veriself query --metrics subject.sleep_debt_7d --dimensions date.weekday --role owner   # 立刻被拒（退出码 3）
veriself init                                                                     # 重新物化，数值随之变化
```

**看懂标志**：你能解释为什么改一个 YAML 字段会立刻改变系统行为，而**不需要改一行 Python**。
